# ADR 0002. Схема БД: одиночный SQL-скрипт вместо миграций

Дата: 2026-09-30 Статус: принято

## Контекст

ТЗ разрешает скрипт или миграцию. Выбран Dapper, 
поэтому `EF Core Migrations` как стандартный источник миграций
тянули бы целый `EF` в проект ради одного `DDL`.

## Решение

Один идемпотентный по смыслу скрипт [`db/init/01_schema.sql`](../../db/init/01_schema.sql), 
применяемый автоматически через [`docker-entrypoint-initdb.d`](../../docker-compose.yml) 
при первом старте контейнера.

## Последствия

Изменение схемы при разработке - `docker compose down -v` а потом поднимаем через `docker compose up -d`.
Если решение нуждалось бы в выводе на прод то, подключил бы инструмент миграций: `DbUp` или `FluentMigrator`, 
а для тестового это слишком.
