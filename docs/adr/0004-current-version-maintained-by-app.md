# ADR 0004. current_version_id: поддерживается приложением

Дата: 2026-10-01 Статус: принято

## Контекст

ТЗ требует поддерживать current_version_id при создании и аннулировании версий. 
Требование принято: поле хранится и всегда корректно.

## Альтернативы

- Триггеры БД: надёжно при любых действиях, но логика в бд, не тестируется через xUnit.
- Отказаться от поля, вычислять подзапросом: спор с рекомендованной схемой ТЗ, сложнее и медленнее рекурсивный CTE.
- Сервисный слой: единый сервис версий в транзакции.

## Решение

Третий вариант это единственная точка создания/аннулирования версий - сервис версий,
он же обновляет указатель.

## Последствия

Создание/аннулирование версий - только через сервис версий, сырые `UPDATE` из `UI` и репозиториев запретил.
Все шесть строк таблицы - xUnit тесты;

|Действие|current_version_id|
|-|-|
|Создание объекта (версия 1)| v1|
|Повторный импорт: текущая В работе|не меняется|
|Повторный импорт: текущая Утверждено|новая версия В работе|
|Утверждение текущей версии|не меняется|
|Аннулирование: есть более раннии|последняя неаннулированная|
|Аннулирование последней неаннулированной|NULL|
