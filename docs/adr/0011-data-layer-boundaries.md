# ADR 0011. Слой Data: границы, транзакция, идентификация

Дата: 2026-10-05 Статус: принято

## Контекст

Data это единственный слой связанный с SQL. Техническое задание требует импортировать данные в одной транзакции
MiniPdm.Core по решениям (ADR 0004–0009) не должно знать про id в базе данных.

## Решения

- Распределение такое: Db занимается соединениями, PdmObjectRepository объектами, VersionService отвечает за версии и состояния (по ADR 0004, там один главный писатель), ImportService за оркестрацию, а BomRepository за CTE-дерево.
- Транзакция стартует в ImportService и передается дальше по параметрам. Репозитории соединений сами транзакции не открывают.
- Для идентификации: если объект новый, используем INSERT * RETURNING id. Если существующий берем id из словаря "идентичность id", который загружается из снимка. Снимки для Core остаются без id.
- Когда работаем со снимками: все объекты получаем через пару SELECT-запросов, потом собираем их в памяти по ObjectIdentity.Key. Прямые запросы по кортежам мы отклонили, потому что SQL-хитрости с NULL тут не очень подходят.
- Для доменных enum'ов используем строковые TypeHandler'ы. Dapper по умолчанию отправляет enum как число, а в базе схема хранит его как TEXT (по ADR 0001).
- API VersionService это про конкретные доменные действия, а не просто CRUD. Например, правило "какая версия когда создается" имеет только один вход.
- Версию InWork обновляем прямо на месте: меняем атрибуты через UPDATE и перезаписываем bom_link.
- Логи импорта (import_log) записываем строкой по файлу (Info/Warning/Error) внутри основной транзакции. Если происходит откат, журнал откатывается вместе с данными. Это проверенный подход, он зафиксирован в README.
- Если при чтении возникают ошибки (CadDocumentException), мы дописываем их в Issues в ImportService.
- Тесты делим на два типа: чистые сценарии это транзакции с откатом. Импортные тесты это реальные коммиты с уникальными, корректными данными (по формату ТЕСТ.NNNNNN.00K), после которых мы выборочно всё чистим.

## Последствия

- Типы Npgsql видны в сигнатурах Data намеренно: это внутренний слой, и если бы он использовал IDbTransaction, то потерял бы специфические возможности провайдера.
- Логика работы указателя находится в VersionService, но само решение принимает CurrentVersionRules из Core, так что дублирования кода нет.
