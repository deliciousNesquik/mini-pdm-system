# ADR 0001. Значения-справочники: TEXT + CHECK, не нативный ENUM

Дата: 2026-09-30 Статус: принято

## Контекст
`ObjectType` и `ObjectState` 3 значения это закрытые множества.
`PostgreSQL` предлагает нативный `ENUM`; `MSSQL` - нет, необходим доп механизм.
Техническая документация допускает обе СУБД, поддержка второй - пункт дополнительной части.

## Альтернативы

- Используем нативный enum в `PostgreSQL`: `Dapper` без настройки возвращает строку, а не enum. Непереносимо на `MSSQL`.
- Lookup-таблицы + FK: соединять на каждый запрос ради трёх строк? бойлерплейт! 
- TEXT + CHECK: `Dapper` маппит строку, enum по имени автоматически; правка - обычный DDL; переносимо между СУБД.

## Решение

TEXT поле с CHECK. Имена членов enum в коде обязаны совпадать со значениями в CHECK.

## Последствия

Дублирование значений в двух местах в БД (`pdm_object`, `object_version`) и `C#` `MiniPdm.Core` - контролируется 
тестом-смоков на БД и код ревью. Добавление значения это будет миграция CHECK а также обязательно новый enum, обе правки тривиальны.
