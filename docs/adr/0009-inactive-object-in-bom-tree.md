# ADR 0009. Объект без действующей версии сохраняется в дереве состава

Дата: 2026-10-02 Статус: принято


## Контекст

У объекта может не остаться ни одной рабочей версии: по ADR 0004 можно аннулировать 
все версии — current_version_id станет NULL. Сам объект при этом остаётся в базе, 
и другие сборки продолжают ссылаться на него в своём составе.

Если рекурсивный запрос по дереву сделан через обычный JOIN по current_version_id, 
такой объект молча выпадет из дерева: масса сборки посчитается без него, и никто не заметит. 
Получается неполная сумма а ТЗ прямо запрещает это: расчёт должен назвать, у какого компонента
нет данных, а не выдать похожую на правду цифру.

## Альтернативы

- JOIN по current_version_id тогда узел исчезает из дерева - неполнота, худший вариант.
- Не допускать в БД объекты без действующей версии (запретить аннулировать последнюю) ломает правила состояний из ТЗ, где Аннулировано -легитимный финал любой версии.
- LEFT JOIN помечено как нет действующей версии узел остается в дереве как строка без раскрытия состава - выбрано.

## Решение

CTE возвращает строки дерева с флагом `HasActiveVersion`. Состав такого объекта не раскрывается 
потому что раскрывать нечего а значит текущей версии не существует. `BomCalculator.TotalMass` 
считает узел виновником MassProblemKind.NoActiveVersion и возвращает итог null
сводная спецификация такой узел не считает. UI отображает строку с меткой нет действующей версии.

## Последствия

Инвариант сумма либо точна, либо null с перечнем виновников выполняется для всех причин неполноты и нет массы, и нет действующей версии
Guard против молчаливой неполноты существует в одном месте - BomCalculator. SQL не дублирует проверку.
